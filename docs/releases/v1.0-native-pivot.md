# v1.0.0 — Der Native-Pivot: vom Nachbau zum Governance-Skelett

> 🌐 **Sprache:** Deutsch (diese Datei) · [🇬🇧 English](v1.0-native-pivot.en.md)

> Major-Release-Dokument (BOO-216) nach Sprint 6 — **Vermarktungs- und Migrations-Note**, kein Change-Log. Synthese der Sprint-3-bis-6-Transformation. Geschrieben in Sprint 6 (BOO-215); **Tag/Rollout `v1.0.0` selbst ist post-Sprint-6** (BOO-9, 3-VPS-Rollout). Der aktuell getaggte Stand ist **v0.13.0**. SemVer-Kontext: Sprint 3 → v0.11.0 · Sprint 5 → v0.12.0 · Sprint 6 → v0.13.0 · **Major v1.0.0** danach.

## Executive Summary

Zwischen Sprint 3 und 6 hat INTENTRON seine teuerste Annahme aufgegeben: dass ein Governance-Framework die Orchestrierung **selbst bauen** muss. Mit der Build-vs-Buy-Doktrin (ADR-1) kippt die Logik — alles, was Anthropic nativ liefert (Termination-Schleifen, Subagents mit eigenem Kontextfenster, Cloud-Planung, Status-Line), wird **genutzt** statt nachgebaut. Übrig bleibt das, was Anthropic *nicht* liefert: ein durchgesetztes Governance-Skelett aus Gates, Spec-Pflicht, Compliance-Katalogen und Audit-Spur. v1.0 ist dieser Schnitt — das Framework ist schlanker, schneller und gleichzeitig schärfer abgegrenzt gegenüber dem nackten Standard-Tool. Für Bestandsprojekte ist der Übergang **additiv und idempotent**: nichts bricht, die nativen Pfade schalten sich nur dort frei, wo das Projekt auf Claude Code läuft.

## Operator-Migrations-Pfad (0.x → 1.0)

Bestandsprojekte ziehen idempotent und nicht-destruktiv nach:

1. **`intentron migrate`** — führt die kumulierten `migrate_boo_*()`-Schritte aus (u.a. `migrate_boo_199` Schalter A + Native-Pfade-Block, `migrate_boo_200` Automemory-Header, `migrate_boo_205` Status-Line). Setzt `runtime_target` **nur**, wenn unbestimmt; eine explizite `codex`/`cross-tool`-Wahl bleibt unangetastet.
2. **`bash scripts/verify-setup.sh`** — prüft die neuen Verdrahtungen (§4b Native-Pfade, §4c Automemory-Header, §5c Status-Line).
3. **Migrations-Runbook** [`../runbooks/framework-update.md`](../runbooks/framework-update.md) — der geführte `inspect → apply-safe → apply-with-confirmation`-Ablauf (Detail: `references/framework-upgrade.md`).
4. **Bestands-Onboarding** — HANDBUCH **Anhang U** (Projekt 2..N + bestehendes Projekt onboarden).

Wer `codex`/`cross-tool` fährt, muss nichts tun: die nativen Pfade bleiben inaktiv (Schalter-A-Kopplung).

## Schalter-Übersicht A / B / C

Die nativen Pfade sind opt-in über drei Schalter-Gruppen — aktiv nur bei `runtime_target: claude-code` (`native_paths`-Block der CLAUDE.md).

| Gruppe | Schalter | Default | Wirkung |
|--------|----------|---------|---------|
| **A** | `runtime_target` | `claude-code` (Neuanlagen) | Aktiviert die Native-Pfade überhaupt; Bestand bleibt, bis migriert |
| **B** | `prefer_native_subagents` | `true` | `/implement` erzeugt echte native Subagents (eigenes 200k-Fenster) |
| **B** | `prefer_goal_termination` | `true` | `/sprint-run` + lange `/implement`-Läufe terminieren über `/goal` |
| **B** | `prefer_ultraplan` | `auto` | `/architecture-review` + `/ideation` schlagen `/ultraplan` bei Stories > 5 SP vor |
| **B** | `complement_insights` | `true` | `/sprint-review` ergänzt natives `/insights` (Skill `insights-review`) |
| **C** | Routinen-Runbook | — (kein Bootstrap-Default) | Wiederkehrende Routinen kommen als kopierfertiges Runbook statt als Setup-Frage |

# 🇬🇧 English Version

# v1.0.0 — The native pivot: from rebuild to governance skeleton

> Major release document (BOO-216) after Sprint 6 — a **marketing and migration note**, not a change log. Synthesis of the Sprint-3-to-6 transformation. Written in Sprint 6 (BOO-215); the **`v1.0.0` tag/rollout itself is post-Sprint-6** (BOO-9, 3-VPS rollout). The currently tagged state is **v0.13.0**. SemVer context: Sprint 3 → v0.11.0 · Sprint 5 → v0.12.0 · Sprint 6 → v0.13.0 · **major v1.0.0** afterwards.

## Executive summary

Between Sprint 3 and 6, INTENTRON dropped its most expensive assumption: that a governance framework has to **build** the orchestration itself. The build-vs-buy doctrine (ADR-1) flips the logic — everything Anthropic ships natively (termination loops, subagents with their own context window, cloud planning, the status line) is **used** instead of rebuilt. What remains is what Anthropic does *not* ship: an enforced governance skeleton of gates, spec obligation, compliance catalogs and an audit trail. v1.0 is that cut — the framework is leaner, faster and at the same time more sharply delimited against the bare standard tool. For existing projects the transition is **additive and idempotent**: nothing breaks, the native paths only switch on where the project runs on Claude Code.

## Pitch — what INTENTRON does that the Anthropic standard does not

Canonical list from **HANDBUCH Appendix AP** (BOO-209, source ADR-1). These are the 13 deliberate in-house builds — the build share that carries the differentiation. Everything else was handed to the native engine.

| # | Component | What it delivers | Anthropic counterpart |
|---|-----------|------------------|-----------------------|
| 1 | `/intent` (Schrader's 5 steps) | Enforces "why before spec" — methodical intent before code | — |
| 2 | `/pitch` (demo-path heuristic) | Collects stakeholder evidence along a demo path | — |
| 3 | Three-layer quality-gate architecture | Staged Semgrep/coverage/slopsquatting scaffold | — |
| 4 | Layer-0 PreToolUse bodyguard | Deterministic edit gate *before* writing | — |
| 5 | Spec gate as a git hook | "No commit without a spec", machine-enforced | — |
| 6 | dpo control catalog (nDSG/GDPR/NIST as YAML) | Privacy compliance as a deterministic catalog | — |
| 7 | CONVENTIONS.md (tool-neutral anchor) | Adapter contract across Claude/Codex | — |
| 8 | AGENTS.md generator | Portable Codex entry (tool neutrality) | — |
| 9 | Knowledge-onboarding skill | Routes existing docs into framework artifacts | — |
| 10 | DevContainer template | Pre-configured, governance-ready container | — |
| 11 | Quality-gate self-audit | Checks whether gates are *actually wired* | — |
| 12 | `change_type: prototype` | Deliberate gate relaxation without breaking compliance | — |
| 13 | Vendored cross-cutting skills | Bundled experts (security, DPO, cloud) | — |

Honest delimitation: orchestration, subagents, planning and status display are **not** on this list — Anthropic ships those natively, which is exactly why the framework no longer builds them.

## Operator migration path (0.x → 1.0)

Existing projects catch up idempotently and non-destructively:

1. **`intentron migrate`** — runs the accumulated `migrate_boo_*()` steps (incl. `migrate_boo_199` switch A + native-paths block, `migrate_boo_200` automemory header, `migrate_boo_205` status line). Sets `runtime_target` **only** when unset; an explicit `codex`/`cross-tool` choice stays untouched.
2. **`bash scripts/verify-setup.sh`** — checks the new wirings (§4b native paths, §4c automemory header, §5c status line).
3. **Migration runbook** [`../runbooks/framework-update.md`](../runbooks/framework-update.md) — the guided `inspect → apply-safe → apply-with-confirmation` flow (detail: `references/framework-upgrade.md`).
4. **Existing-project onboarding** — HANDBUCH **Appendix U** (project 2..N + onboarding an existing project).

If you run `codex`/`cross-tool`, there is nothing to do: the native paths stay inactive (switch-A coupling).

## Switch overview A / B / C

The native paths are opt-in via three switch groups — active only under `runtime_target: claude-code` (the CLAUDE.md `native_paths` block).

| Group | Switch | Default | Effect |
|-------|--------|---------|--------|
| **A** | `runtime_target` | `claude-code` (new projects) | Activates the native paths at all; existing projects stay until migrated |
| **B** | `prefer_native_subagents` | `true` | `/implement` spawns real native subagents (own 200k window) |
| **B** | `prefer_goal_termination` | `true` | `/sprint-run` + long `/implement` runs terminate via `/goal` |
| **B** | `prefer_ultraplan` | `auto` | `/architecture-review` + `/ideation` suggest `/ultraplan` for stories > 5 SP |
| **B** | `complement_insights` | `true` | `/sprint-review` complements native `/insights` (skill `insights-review`) |
| **C** | Routines runbook | — (no bootstrap default) | Recurring routines come as a copy-ready runbook instead of a setup question |

## Before / after — sprint-run old vs. /goal engine

| Aspect | Before (0.x, `/sprint-run` orchestrator) | After (1.0, `/goal` engine) |
|--------|------------------------------------------|------------------------------|
| Termination | In-house loop + planned hybrid container (BOO-184, cancelled) | Native `/goal` loop until "all gates green", then a clean stop |
| Parallelism | Script-orchestrated worktrees | Native subagents with their own context window per story |
| Planning large stories | manually triggered | `/ultraplan` suggestion automatically above > 5 SP |
| Sprint evaluation | framework's own sprint review only | + native `/insights` (complementary) |
| Progress view | in the report, after the fact | live in the native status line (model, budget, worker-equivalent) |
| Role of the framework | engine **and** governance | **governance skeleton**, Anthropic provides the engine |
