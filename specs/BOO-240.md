# BOO-240 — Runbook: Developer-VPS vom Handy steuern (Claude Remote Control + tmux)

## Summary

Neues zweisprachiges Runbook `docs/runbooks/vps-vom-handy.md` (+ `.en.md`): eine auf der VPS laufende Claude-Code-Session vom Handy **beobachten und steuern** — Claudes **Remote-Control**-Feature kombiniert mit der bestehenden tmux-Best-Practice. Reine Doku. Quelle: Operator-Wunsch 2026-06-20.

## Why

Es gab ein tmux-Runbook (`sprint-unattended-tmux.md`), aber keines zu „Claude Remote Control vom Handy" und zur Kombination mit tmux. Operatoren, die unterwegs eine laufende VPS-Session begleiten wollen, mussten raten, welches Feature das real leistet — mit dem Risiko, einen Workaround (SSH-App, Tunnel) statt der offiziellen Funktion zu dokumentieren.

## What

- **Mechanismus verifiziert (nicht angenommen):** Remote Control gegen die offizielle Claude-Code-Doku geprüft (claude-code-guide-Agent gegen [code.claude.com/docs/en/remote-control](https://code.claude.com/docs/en/remote-control)). Belegt im Runbook: offizielle Funktion „Remote Control" (Research Preview); Compute läuft **auf der VPS** (nicht in der Cloud); Plattform claude.ai/code + Claude-App (iOS/Android); Voraussetzung **Abo Pro/Max/Team/Enterprise, kein API-Key**; Auth via `/login`; nur **ausgehendes HTTPS**, keine Inbound-Ports; Reichweite beobachten/steuern/Dateien-via-`@`/MCP.
- **Remote Control vs. tmux** klar abgegrenzt: tmux = Prozess-Persistenz auf der VPS (überlebt SSH-Abbruch/SIGHUP); Remote Control = Handy-Fenster über die Anthropic-API. **Kombination:** Claude in tmux + Remote Control aktiv.
- **Step-by-step:** SSH → tmux → `/remote-control` (bzw. `claude --remote-control`) → vom Handy verbinden → `Strg+B D` detach → wieder andocken (tmux `attach` / App-Reconnect).
- **Security:** keine offenen Ports für Remote Control; keine Token pasten (claude.ai-`/login`-Session); **mobil = beobachten + steuern + Branch/PR**, Merge/Deploy/Secrets bleiben **menschlich-gated** (Verweis README „Unsere Position", BOO-227).
- **Grenzen:** lokaler Prozess muss laufen (→ tmux; gegen Reboot → Headless/systemd); ~10-Min-Netz-Timeout; interaktive Picker lokal; Research Preview.
- **INDEX DE+EN** ergänzt; **README-Operations-Verweis** um die Remote-Variante erweitert.

## Constraints

- **Anti-Fabrikation:** keine angenommenen Fähigkeiten — nur das gegen die offizielle Doku Verifizierte. Keine harte Versionsnummer fest verdrahtet (stattdessen „aktuelle Version, Update falls `/remote-control` fehlt"), kein QR-/Detail-Claim ohne Beleg.
- Klare Trennung gegenüber „Claude Code on the web" (Cloud) — Remote Control läuft auf der eigenen VPS.
- **Menschlich-gated** bei irreversiblen Aktionen (Merge/Deploy/Secrets) explizit benannt.
- Optionaler Sketch („ggf.") **bewusst weggelassen** — das mentale Modell trägt der Text + die Tabelle; konsistent zu `headless-vps` (ebenfalls ohne Sketch).
- DE/EN paritätisch; Verbund-Vernetzung (Anhang-Y-Hub, Geschwister-Backlinks) im Capstone BOO-245 (gleiche PR).
