## Summary

Schalter B (`prefer_native_subagents: true`, in 5a/BOO-199 als CLAUDE.md-Flag definiert) wird in
`/implement` **konsumiert**. Heute brieft `/implement` Story-interne Subagents als Text-Block im gleichen
Kontextfenster (simulierte Choreografie via Agent-Tool); nur der `lint-fixer` läuft optional schon als
`.claude/agents/`-Definition. Neu: Wenn `prefer_native_subagents: true` und die Spec eine
**Subagent-Sektion** deklariert, generiert `/implement` daraus on-the-fly echte
`.claude/agents/<story>-<agent>.md`-Dateien — jeder Agent mit **eigenem 200k-Kontextfenster**, eigenen
Tool-Permissions, optional eigenem Modell. Die Spec bleibt Quelle (sequenziell vs. Subagents, welche
Agents). Worktree-Isolation (`execution_isolation`) bleibt orthogonal. Beide Patterns (alt = gleiches
Window, neu = native Subagents) werden in SKILL.md+.en.md dokumentiert.

## Why

ADR-2 [Claude-Code-first Pivot](https://linear.app/owlist/issue/BOO-199) Schalter B: Das Framework soll
Anthropics native Subagent-Choreografie nutzen statt sie im gleichen Kontextfenster zu simulieren.
Simulierte Subagents teilen sich das 200k-Window des Orchestrators — bei mehreren Agents pro Story wird
das Fenster knapp und die „Isolation" ist nur nominell. Native Subagents bekommen je ein eigenes
Fenster, eigene Tool-Permissions und ein eigenes Modell — echte Isolation, mehr nutzbarer Kontext,
sauberere Audit-Spur. `/sprint-run`→`/goal` (ADR-4) generiert solche Agent-Definitionen bereits auf
**Sprint-Ebene** (Schritt 4.2, aus der Subagent-Sektion der Spec). BOO-204 bringt dasselbe Pattern auf
die **Story-Ebene** in `/implement`, gesteuert durch das Flag — damit auch der Einzel-Story-Lauf
(`/implement` ohne `/sprint-run`) native Subagents nutzt.

## What

1. **Spec-Konvention „Subagent-Sektion" festschreiben** — `/implement` braucht eine Quelle. Definiere
   in `implement/SKILL.md` (+ `.en.md`) das Format einer optionalen `## Subagents`-Sektion in der
   Story-Spec: pro Agent ein Eintrag mit `name`, `role`, `model` (optional), `tools`/`permissions`
   (optional), `write_scopes`. Konsistent mit der Sektion, die `/sprint-run` Schritt 4.2 schon liest
   (gleiches Format, ein SSoT — nicht zwei divergierende Konventionen).
2. **Flag-Konsumption in `/implement` Schritt 0** — `/implement` liest `native_paths.prefer_native_subagents`
   aus der `CLAUDE.md` des Projekts (heute liest Schritt 0 nur `.claude/environment.json`). Vorbild:
   wie `bootstrap` CONVENTIONS.md liest. Fehlt das Flag → Default `true` (ADR-2). Bei
   `runtime_target ≠ claude-code` → Flag inaktiv (Schalter-A-Kopplung, Native-Pfade gelten nur bei
   claude-code).
3. **Generator-Logik** — wenn `prefer_native_subagents: true` UND Spec hat `## Subagents`: vor der
   Code-Phase erzeugt `/implement` pro Agent eine `.claude/agents/<story>-<agent>.md` (Rolle,
   Worktree-Pfad falls isoliert, `write_scopes`, Story-ID, Gate-Liste, Modell, Tool-Permissions). Wenn
   `false` ODER keine Subagent-Sektion → bisheriges Verhalten (Text-Block-Briefing im gleichen Window).
   Der bestehende `lint-fixer`-Pfad (Schritt 6a, `references/lint-fixer.agent.md`) wird unter dieselbe
   Generator-Logik gezogen (ein Mechanismus, nicht zwei).
4. **AC#3 — Pro-Story konfigurierbar:** Modell, Tools, Permissions je Agent aus der Subagent-Sektion
   ableitbar; Default-Werte dokumentieren (z.B. Code-Kern bleibt Opus, Hilfs-Agents günstigeres Tier).
5. **AC#4 — Worktree-Isolation orthogonal:** `execution_mode`/`execution_isolation`/`worktree_strategy`
   (Schritt 0c) bleiben unverändert und unabhängig vom Native-Subagent-Flag. Native Subagents + Worktree
   sind kombinierbar, nicht gekoppelt.
6. **AC#5 — Pattern-Doku:** `implement/SKILL.md` + `.en.md` erklären „altes Pattern (gleiches Window,
   Text-Block-Briefing) vs neues Pattern (native Subagents mit eigenem 200k-Window)" und wann welches
   greift (Flag + Subagent-Sektion vorhanden).
7. **AC#6 — README:** `implement/README.md` + `.en.md` aktualisiert; Version-Bump `2.15.0` → **2.16.0**
   (SKILL+README, DE+EN, docs-drift-Parität).
8. **AC#7 — Sketch:** `implement/overview.excalidraw` (+ `.en`) aktualisiert — neues Architektur-Diagramm
   mit eigenen Kontextfenstern pro Subagent; Render-Loop (npx excalidraw_export → rsvg-convert → Read-
   Sichtprüfung) für `overview.png` + `overview.en.png`.
9. `docs-drift` rc=0; diese Spec → Result; Vault-Skill-Doku `03 Bereiche/Skills/code-crash/implement.md`
   (+ `.en.md`) nachziehen; Release/Wave im Sammel-Cut v0.12.0 (Sprint-5-Ende).

## Constraints

- **Ein SSoT für die Subagent-Sektion.** Das Spec-Format, das `/implement` liest, MUSS dasselbe sein,
  das `/sprint-run` Schritt 4.2 liest — keine zweite, divergierende Konvention. Falls `/sprint-run`
  bereits ein implizites Format hat, dieses dokumentieren und wiederverwenden.
- **Abwärtskompatibel.** Specs ohne `## Subagents`-Sektion laufen wie bisher (Text-Block / gleiches
  Window). Das Flag schaltet nur das *Wie*, nicht das *Ob* der Story-Ausführung.
- **Schalter-A-Kopplung.** Bei `runtime_target ≠ claude-code` ist `prefer_native_subagents` inaktiv —
  diese Regel aus dem Native-Pfade-Block (BOO-199) respektieren.
- **Skill = Instruktionen, kein Code.** `/implement` ist ein LLM-Skill; „Generator-Logik" heißt
  präzise SKILL.md-Anweisungen, kein Bash-Generator. Anti-Fabrikation: keine erfundenen Tool-/Pfad-Namen.
- **`.claude/agents/`-Hygiene.** Generierte Story-Agent-Dateien sind transient; klären, ob sie nach dem
  Lauf entfernt/ge-`.gitignore`-d werden (wie `/sprint-run` sie handhabt — gleiche Konvention).

## Abgrenzung

- **Sprint-Ebene-Orchestrierung** (`/sprint-run`→`/goal`, parallele Stories als native Subagents) =
  bereits vorhanden (ADR-4, BOO-203). BOO-204 ergänzt die **Story-Ebene** in `/implement`, nutzt aber
  dieselbe Agent-Definitions-Konvention.
- **`/rewind`-Doku in `/implement`** = **BOO-208** (gleicher Slice 5b-1, eigene Spec).
- **`prefer_ultraplan`-Konsumption** (`/architecture-review` + `/ideation`) = **BOO-207** (5b-2).
- **Flag-Definition** (`native_paths`-Block im CLAUDE.md-Template) = bereits in BOO-199 (5a) erledigt.
