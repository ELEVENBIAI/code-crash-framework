# BOO-254 — CI-Spec-Gate: server-seitiges Spec-Linkage-Gate (opt-in)

## Summary
Ein **opt-in** GitHub-Actions-Workflow `spec-gate-ci.yml` (`name: Spec-Linkage`), der auf jedem PR nach `main` server-seitig prüft, dass die Änderung eine existierende `specs/<ISSUE>.md` referenziert (Issue-Key aus Branch-Name + PR-Titel, Pattern `[A-Z]+-[0-9]+`, squash-merge-fest). Findet keinen Bezug → Job failt → PR nicht mergebar. Scaffold-bar als Template, aktivierbar als Required Status Check via `setup-branch-protection.sh`-Re-Run. Schliesst die im Enforcement-Selbst-Audit (Research Datei 08) benannte Lücke des Runtime-Spec-Gates.

## Why
Das Spec-Gate ist heute ein Claude-Code-`PreToolUse`-Hook: es blockt den KI-Agenten mechanisch (Exit 1), greift aber **nur in der Claude-Session**. `git commit --no-verify`, ein menschlicher Commit ausserhalb Claude oder ein anderes Tool umgehen es — es gibt **kein server-seitiges (CI) Spec-Linkage-Gate**. Diese Vertrauensgrenze ist in HANDBUCH Anhang AV (BOO-228 Teil 1) offen benannt und in der README-Positionierung als „✅ Runtime¹" (nicht voll-✅) ehrlich gescopet. BOO-254 macht „kein Merge ohne Spec" auch gegen `--no-verify` und Nicht-Claude-Pfade wahr — und ist der Schritt, den keiner der 2026-Wettbewerber hat (Spec Kit `/analyze` read-only, agentic-os honor-system).

## What
- **Artefakt** `bootstrap/references/file-templates.md` + `.en.md`: neuer Heredoc-Block `## .github/workflows/spec-gate-ci.yml` (SSoT-Triplikat — gleicher Block auch im migrate-Skript). Logik: Keys aus `github.head_ref` + `pull_request.title` (nicht Commit-Messages → squash-fest), bestanden sobald **eine** `specs/<KEY>.md` existiert, sonst Exit 1. `name: Spec-Linkage` → wird von `setup-branch-protection.sh` automatisch als Required-Kontext erkannt.
- **Opt-in via Bestands-Konvention (Anhang AT, Erweiterungs-Regel):** **kein neuer Interview-Schritt** — der literale „Setup-Frage"-Wunsch des Issues wird per dokumentierter Leichtgewicht-Regel als **§7.7-Post-Install-Pointer** umgesetzt (bootstrap `SKILL.md`/`.en.md` + `developer-onboarding-template.md`/`.en.md`), Empfehlung für `governance_mode = heavy`. Begründung: Anhang AT verbietet neue Interview-Fragen für Opt-in-Add-ons ausdrücklich.
- **migrate** `bootstrap/scripts/migrate-to-v2.sh`: `migrate_boo_254()` legt `.github/workflows/spec-gate-ci.yml` an, falls es fehlt (idempotent, nicht-destruktiv), + Dispatch nach `migrate_boo_239`.

## Acceptance Criteria
